# IWPODv3 (DPOD + modern upgrades)

Vehicle-crop quad detector. Same contract as v2 unless noted:
`[B,7,Gh,Gw]` raw logits + affine6, stride 16, `SIDE=7.75`,
top-left letterbox, warp `256x96`.

## Arch versions (stamped in ckpt `arch`, checked on export)

| `arch_version` | Backbone | Head | Outputs | DS plugin |
|---|---|---|---|---|
| `v2` | orig dense `Conv-BN-ReLU` | orig dense | `lpd_pred` | unchanged |
| `v3-s16` (default upgrade) | `rep` (RepVGG reparam: train `3x3+1x1+id`, infer single `3x3`) | `dw` depthwise-sep + optional `SimAM` | `lpd_pred` | unchanged (drop-in) |

(The former `v3-fpn` stride-8 P3 head was removed 2026-09-14: plates are
92px median in-crop with the sub-48px slice already at IoU@0.7 0.93, so it
had no measurable target. Stale `v3-fpn` checkpoints/configs fail loud.)

`backbone=orig/head=orig` reproduces v2 exactly (old checkpoints load unchanged;
`build_model_for_ckpt` reads `arch` meta with fallback to orig).

## What changed and why (verified sources)

* **Reparam backbone** (`iwpod/network.py:RepConvBlock`): RepVGG CVPR21 —
  +accuracy at iso-latency, 83%/101% faster than ResNet-50/101 on GPU;
  YOLOv6/v7 production path. Infer graph = same `Conv/ReLU/MaxPool/Add`
  ops as v2, so TRT 8.5/10 + OpenVINO safe. `switch_to_deploy()` is
  parity-tested (`tests/test_v3_upgrades.py::test_rep_parity_train_vs_deploy`).
* **DW-Sep + SimAM head** (`DWConvBatch`, `SimAM`): YOLO-LBS —
  -36% weight/-34% FLOPs/+5% mAP class. SimAM is parameter-free
  (`mean/var/sigmoid`), no TRT plugins. Measured deploy-fused @416
  (ORT CPU, median of 30): v2 1.82M/9.8ms, rep 1.82M/9.8ms
  (identical infer graph — reparam is a training-capacity play),
  rep+dw+simam 1.66M/9.6ms (-9% params, latency-neutral on CPU;
  re-measure GPU/TRT per platform with `trtexec`).
* **Corner loss: Wing only — LPWing removed** (was `iwpod/loss.py:lpwing_loss`,
  deleted 2026-09-14): LPWing gradients measured ~15x smaller than Wing on
  real val batches (25x on values). At `w_loc=1.0` it starved corners late
  (`lpr_v3`: IoU@0.9 0.42 vs 0.62); at `w_loc=12.0` it over-drove them ~7x
  early, distorting shared features and freezing `cls` 2x high (`gate_loss`
  isolation run). The analytic gradient sweep (ratio 1.7x at large errors →
  10x near zero) shows no constant weight can match both regimes. Stale
  configs carrying `loss.loc_type` fail loud in `validate_config` instead of
  silently changing behavior.
* **Copy-paste augmentation: removed** (was `sampler.py:_copy_paste_plate`,
  deleted 2026-09-14): correlated with doubled false positives (23 vs 10)
  plus a mid-training `val_cls` spike; never isolated, never positive.
  Stale configs carrying `augment.copy_paste_p` fail loud.
* **Detail boosting** (`sampler.py`, `dataset.py`): per-sample plate-scale
  jitter, `augment.detail_boost` (e.g. 0.5 = ±50%). In the passing
  `gate_v3b` bundle; defaults 0.0 = v2 behavior.
* **LP-NME metric** (`eval_core.py:lp_nme`): Wei & Xie 2023, mean corner
  error / GT diagonal. Reported next to RMSE in `EVAL` blocks and
  `val_log.txt`; promotion still gates on mAP@50-95 first.

## Config (configs/base.yaml)

```yaml
model: {arch_version: v2, backbone: orig, head: orig, use_simam: false}
loss: {w_cls: 1.0, w_dice: 0.5, w_loc: 1.0}
augment: {detail_boost: 0.0}
```

`--arch v3` (= the `gate_v3b` bundle that passed the 8-epoch gate):

```yaml
model: {arch_version: v3-s16, backbone: rep, head: dw, use_simam: true}
loss: {w_cls: 1.0, w_dice: 0.5, w_loc: 1.0}
augment: {detail_boost: 0.5}
```

## Ship path (unchanged workflow)

```bash
# v3-s16 (recommended first upgrade; --arch bundles the flags below)
iwpod train --data datasets/LPR --epochs 200 --batch-size 32 --lr 0.001 \
  --arch v3 --name v3s16
iwpod eval --weights out/train/v3s16/v3s16_best.pth --data datasets/LPR/val --size 416 --sweep 0.15 0.25 0.4 0.5 0.6
iwpod export -w out/train/v3s16/v3s16_best.pth -s 416 --dynamic --dynamic-shape --simplify --check-parity -o iwpod_v3_416.onnx
# DeepStream builds the engine on-target (FP16 default); INT8 needs --calib crops.
```

Without flags, `iwpod train` is v2 behavior (all v3 knobs default off) —
your plain `iwpod train --data ... --epochs 100 --batch-size 64 --name lpr`
does **not** use the upgrades until you add the flags (or set them in YAML).

* FP32 ONNX master, opset 17, `%32` sizes. `--fuse` folds Rep+BN
  (re-run `--check-parity`, tol 1e-4, incl. batch-2).
* v3-s16 exports single `lpd_pred` — existing
  `config_infer_secondary_iwpod.txt` + `libcustom_iwpod_ocr_preprocess.so`
  work unchanged.
* Gates: new `_best.pth` only on held-out mAP@50-95 (tie-break
  IoU@0.7 → IoU@0.5 → recall → LP-NME → vloss); FP16 <1pp / INT8 <0.5pp
  recall drop vs FP32 at operating thr.

## Verdict (2026-09-14, updated: FPN removed 2026-09-15)

100-epoch head-to-head is a tie with v3b ahead where it matters (recall,
mIoU, F1, −9% params) and behind only on IoU@0.9 (−1.8pp) plus a phantom FP
gap that forensics debunked as missing annotations. The corner-order bug
hit both models equally, so the tie likely *understates* v3b. Ship path:
retrain `--arch v3` on cleaned labels; keep `lpr_best.pth` until the clean
retrain confirms. v3 is the primary, v2 the fallback.
(Former v3-fpn P3 head removed: plates are 92px median in-crop, sub-48px
slice already at IoU@0.7 0.93 — no measurable target. In git history if
plate-size distribution ever changes.)

## Label-noise finding (2026-09-14, FP forensics)

The FP gap (v3b 23 vs v2 10 on known-negative crops) is mostly **missing
annotations, not model errors**: 4/4 inspected high-confidence v3b-only
"FPs" contain clearly readable plates with 0-byte `.txt` files, and 9/10
v2 FPs are shared (both models firing confidently = real plates).
`val/` has 28 empty-txt crops, `train/` has 100 — nearly all `Merthyl_*`
scenes — and empties train as all-background, so the same noise both
contaminates the FP metric and poisons training. Fix the labels before
any FPN decision: annotate (or quarantine) the empties, then retrain.

1. v2 baseline (frozen numbers above — rerun to confirm)
2. v3-s16 (`--arch v3`: rep + dw/SimAM + detail-boost — **passed** the 8-epoch
   gate: mAP 0.661 vs v2 0.656, IoU@0.8 0.743 vs 0.749; full 100-epoch run tied v2 at 0.817)

Opt-ins (all default to v2 behavior — nothing changes unless you set them):

```yaml
model: {backbone: rep}          # reparam capacity, identical deploy graph
model: {head: dw, use_simam: true}  # -9% params, in the passing gate bundle
augment: {detail_boost: 0.5}    # in the passing gate bundle
loss: {w_cls, w_dice, w_loc}    # manual loss weights via --w-loc etc.
```

Legacy weights note: pre-2026 checkpoints store `*.conv.bias` (TF port)
while the model uses `bias=False`; `ckpt.load_state_dict_compat` folds
them into `bn.running_mean` (exact, tested in `test_legacy_conv_bias_folding_is_exact`).
Previously `iwpod eval/infer/export/train --resume` all crashed on these
weights — verified broken on the clean tree before this fix.
